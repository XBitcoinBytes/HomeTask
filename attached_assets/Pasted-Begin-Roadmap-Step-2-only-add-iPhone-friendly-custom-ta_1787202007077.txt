Scope:

Add an accessible, mobile-friendly interface for creating one custom task and assigning it to any valid existing room, including built-in rooms.

Required behavior:

- The user can clearly discover and open the task-creation interface on an iPhone-sized screen.
- Opening and cancelling the form changes no data.
- Every input has a visible label and an accessible name.
- Required values are validated before persistence.
- Whitespace is normalized safely without changing meaningful content.
- A collision-safe custom identifier is generated that cannot conflict with built-in or existing custom task IDs.
- The user can assign the task to any valid existing room, including a built-in room.
- Successful submission creates exactly one record marked `_custom: true` through the v1 repository.
- The created task appears immediately in the correct room.
- It survives save/reload, application restart, backup export, and restore.
- Repeated taps or submissions while saving cannot create duplicates.
- A persistence failure does not create a partial task, erase existing data, or discard the user’s entered values.
- Failure is communicated with an accessible error message.
- Focus moves appropriately when the interface opens, succeeds, fails, or closes.
- Keyboard-only operation works.
- Interactive controls have comfortable iPhone touch targets, with a target of at least 44×44 CSS pixels where applicable.
- The form remains usable with the iPhone on-screen keyboard and at narrow viewport widths.
- Existing built-in and custom tasks remain unchanged except for the newly created task.
