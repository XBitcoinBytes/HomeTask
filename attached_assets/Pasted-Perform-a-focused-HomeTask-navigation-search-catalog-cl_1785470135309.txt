1. ADD A SAFE HOME SCREEN

Make the “HomeTask” brand in the upper-left a real button or link with the accessible name:

“Go to HomeTask Home”

Clicking it must always take the user to a clean, calm Home screen.

The Home screen should function like a simple front sign. It should not show the complete task list.

Include large, understandable directions:

- Today
- This Week
- Browse Rooms
- All Tasks
- Backup & Restore

Also show a calm workload summary such as:

“5 tasks due today”

The Home screen must:

- close any open dialog
- close search
- scroll to the top
- clear transient search results
- provide an obvious safe place when the user feels lost
- never change completion history, skips, due dates, or task data
- never trigger onboarding again
- retain existing saved task state

The HomeTask control must have a minimum 44×44px touch target even if the visible text is smaller.

Give it a visible pressed and keyboard-focus state without making it look like a conventional rectangular button.

Decide and document whether a fresh normal launch opens Home or Today. Recommended behavior:

- first launch after onboarding → Home
- later launches → restore the user’s most recent main destination
- tapping HomeTask always → Home

2. COMPACT SEARCH CONTROL

The full-width search bar currently consumes too much permanent space.

Replace its resting state with a compact 44×44px magnifying-glass button.

Tapping the icon should open a dedicated Search sheet or expandable search panel.

Use a proper inline SVG magnifying-glass icon. Remove the broken green left-parenthesis-like shape currently appearing beside the cursor.

The active search field may retain the green flashing insertion cursor.

The search interface must include:

- a clear Search heading
- a text field
- a Clear button when text exists
- a Close button
- recent searches
- useful suggestions before typing
- grouped results
- a calm empty state

Do not leave the large search input permanently visible in the normal task interface.

3. FIX SEARCH SCOPE

Search must work across the complete active task and room catalog, regardless of whether the user was previously viewing Today, This Week, or a filtered room.

Searching must match:

- task title
- room or zone name
- relevant task tags
- relevant room category or aliases

Search must be case-insensitive and whitespace-normalized.

Required examples:

- “Kitchen” finds the Kitchen and its tasks.
- “bathroom” finds Master Bathroom and other bathroom-type rooms.
- “bath” finds Master Bathroom, Half Bath, Madi Bath, and Basement Bath.
- “baseboards” finds every Clean Baseboards task.
- “smoke” finds Check Smoke Detector Batteries.
- “water softener” finds Check Water Softener.

Add a small alias system so semantically equivalent searches work:

- bath ↔ bathroom
- office ↔ study, where appropriate
- trash ↔ garbage
- couch ↔ sofa

Do not use fuzzy matching so broad that unrelated results appear.

Search results should be grouped by room and show each task’s current status.

Selecting a result should open or reveal that task in its room without losing the user’s saved task data.

Closing Search should return to the previous Home, Today, Week, All Tasks, or room context.

4. RECENT AND SUGGESTED SEARCHES

When Search opens with an empty field, show:

Recent Searches

Do not hard-code suggestions that return no results.

5. IMPROVE ROOM AND ZONE CLARITY

Room and zone names are currently too small and visually recessive.

Make the active room or zone name substantially more prominent:

- approximately 22–26px on iPhone
- strong readable contrast
- normal Title Case rather than tiny all-capital lettering
- adequate breathing room
- associated task count or current-view count

When a room is selected, show a clear heading such as:

“Madi’s Room”

Then distinguish these states:

- “No tasks have been added to this room.”
- “Nothing is due in this room today.”
- “No tasks in this room match your search.”

If a room has tasks but none are due in Today view, provide:

“View All Tasks In This Room”

Do not make the user think the room is empty when its tasks are merely outside the selected time view.

Keep room headings readable for older users and large-text settings.

8. DO NOT ADD SWIPE GESTURES

Do not attach behavior to horizontal dragging yet.

Reasons:

- Safari uses edge swipes for Back navigation.
- Horizontal task gestures can cause accidental actions.
- Swipe-only controls are inappropriate for older users and VoiceOver users.
- The navigation model must be validated before adding gesture shortcuts.

Do not add swipe-to-delete, swipe-to-complete, or swipe-to-skip.
