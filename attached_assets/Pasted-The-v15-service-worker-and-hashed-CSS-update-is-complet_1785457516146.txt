1. PRESERVE ACTUAL MALFORMED DATA

The current recovery description says malformed storage is quarantined using metadata only. Recording only the size and timestamp does not preserve the user’s damaged history.

When a HomeTask-owned storage value cannot be parsed:

- preserve a capped copy of the actual raw damaged string when storage permits
- use a dedicated recovery key
- never copy unrelated localStorage data
- store:
  - detectedAt
  - sourceKey
  - originalLength
  - storedLength
  - truncated
  - rawData
- cap rawData at a documented safe limit, such as 250 KB
- retain only one clearly documented recovery record
- do not silently overwrite an existing undownloaded recovery record
- do not claim that the raw recovery record is a valid HomeTask backup

If storage is too full or unavailable to preserve the raw data, clearly record and report that preservation failed.

2. RECOVERY NOTICE

When recoverable malformed data was detected, show a calm notice in Backup & Restore:

“HomeTask found damaged saved data and reopened safely. Some history may need to be restored from a backup.”

Provide:

- Import Backup
- Download Recovery Data
- Dismiss

Download Recovery Data must create a diagnostic JSON file containing the recovery metadata and capped rawData.

Use a filename such as:

HomeTask-recovery-YYYY-MM-DD.json

The diagnostic file must clearly identify itself as recovery data, not as an importable normal backup.

Do not show the notice repeatedly after dismissal unless a new corruption event occurs.

3. ATOMIC IMPORT STORAGE

A confirmed import must not leave HomeTask partially updated if a storage write fails.

Before import:

- validate the complete backup
- sanitize all task state and preferences
- build the complete destination state in memory
- create a byte-for-byte pre-import snapshot of all HomeTask keys that will change
- verify that the Undo snapshot was successfully saved
- abort without changing current data if the Undo snapshot cannot be saved

Use a dedicated temporary staging key:

- write the proposed destination state to staging
- read it back
- parse and validate it
- only then begin committing final HomeTask keys

If any final write fails:

- restore every changed key from the pre-import snapshot
- verify the restored values
- retain the Undo snapshot
- remove incomplete staging data when safe
- show a calm import-failed message
- keep the app usable

Remove the staging key only after a fully successful commit.

4. INTERRUPTED-IMPORT RECOVERY

At startup, detect an abandoned import staging key.

Use explicit transaction metadata sufficient to determine whether:

- no final writes occurred
- some final writes occurred
- the complete import committed successfully

If completion cannot be proven:

- restore the last known-good pre-import snapshot
- verify the restored storage
- remove abandoned staging data only after recovery succeeds
- show a calm recovery notice
- do not silently accept partially imported state

A completed import must not be rolled back merely because cleanup of the staging key was interrupted. Use a clear committed marker or equivalent transaction state.

5. UNDO IMPORT

Preserve the existing Undo Last Import behavior.

Verify that Undo:

- restores every HomeTask key changed by the import
- restores missing keys as missing rather than as the string “null”
- restores task state and preferences byte-for-byte
- removes or retires the Undo snapshot only after successful restoration
- remains available if restoration fails
- does not affect unrelated localStorage keys

6. STORAGE-FAILURE HANDLING

Explicitly handle:

- localStorage read exceptions
- localStorage write exceptions
- quota-exceeded errors
- failure to save the Undo snapshot
- failure to save staging data
- failure on the first final-key write
- failure on a later final-key write
- failure while rolling back
- failure while removing staging data

Never clear all localStorage.

Never delete the last known-good HomeTask state before a verified replacement or rollback exists.
