Correction 1 — Apply Policy A to All Quarantined User Data

The report incorrectly classifies task state and seed overrides as “not user-owned.”

These are user-owned:

- Completion state
- lastDone and doneToday state
- Skip state
- Tags
- State associated with a user-created task
- User overrides to seed titles, zones, recurrence, or archival state

Dropping any of these while reporting a completely successful import can lose user data or user intent.

Because Policy A was selected, use the following rule:

For schema-v2 imports, any quarantined task, zone, state record, completion event, or override must reject the complete import before live storage changes.

Specific outcomes:

- Unknown seed-format task state: reject with the calm “This backup may come from a newer HomeTask catalog; update HomeTask and try again” message.
- Unknown user-format task state: reject as an incomplete or damaged backup.
- Malformed state record: reject.
- Override addressing an unknown seed item: reject with catalog-compatibility language.
- Override with an invalid recurrence: reject rather than silently dropping the user’s schedule.
- User task or zone that cannot be placed: reject.
- Known tombstone state remains valid and accepted.
- Attempts to override catalog-authoritative safety may continue to be stripped and reported because that field was never valid user authority.
- Deterministic normalization and safe field repairs may continue where they preserve the record’s meaning.

For schema-v2 user-owned records, unknown fields should reject rather than be silently stripped. They may represent data created by a newer compatible build. Existing schema-v1 compatibility may retain its separately documented migration rules.
